Current development

Source-verified foundations, clearly bounded.

Each product below is in Development. The summaries deliberately separate foundations that exist in source from capabilities that remain unimplemented, unaccepted, or production-gated.

01

Home

Local control for the places you live.

Development

GoreeCloud Home

Home

A local-first smart-home platform being built around durable state, device capability contracts, availability, offline behavior, privacy, and portability.

Implemented foundation

Persistent Home, Room, and Device models; SQLite authority; event journal; schema migrations; atomic state/event transactions; capability and availability contracts; separate desired/reported state; loopback health/readiness/status.

Still gated

Physical device control, Matter/Thread/Zigbee/Z-Wave/MQTT/BLE, automations, remote access, cameras, energy, AI/voice, client UIs, accepted platform integrations, and production deployment.

Open repository →

Development

GoreeCloud Home Security

Security

An original GoreeCloud local camera-security platform—not a Frigate fork—focused on bounded media handling, private evidence, and fail-closed security boundaries.

Implemented foundation

Strict camera configuration, protected credential references, loopback-only API, durable event journal, health/readiness/status/camera/event reads, bounded FFprobe media probing, sanitized media state, and a shell-free recording command plan.

Still gated

Recorder execution, sustained/authenticated ingest, ONVIF, retention enforcement, playback/restreaming, motion/object detection and tracking, zones/rules, alerts, recognition features, graphical review UI, and production integrations.

Open repository →
02

Intelligence

Private AI with explicit data and authority boundaries.

Development

GoreeCloud AI

AI

A first-party AI conversation, workspace, knowledge, file, tool, and orchestration environment designed to keep model runtimes replaceable and sensitive operations governed.

Implemented foundation

React/TypeScript client, GoreeCloud-owned backend, backend-managed model discovery and streaming chat, conversation persistence, model roles, Workspaces, private attachments, file quota/deletion lifecycle, Wardveil artifact trust gating, safe text extraction, and non-authorizing knowledge eligibility observation.

Still gated

Production RAG/indexing/retrieval authorization, live production model/runtime acceptance, GoreeCloud Identity, Privacy Shield, Everkeep, Mesh, Wardveil runtime acceptance, exact application GLAZE acceptance, and Stable deployment.

Open repository →
03

Build

Own the workload and development layers.

Development

GoreeCloud Containers

OCI

A GoreeCloud-owned OCI-compatible container and workload platform that keeps mature low-level runtime foundations replaceable behind first-party engine contracts.

Implemented foundation

Typed OCI configuration/runtime lifecycle, supported single-manifest registry retrieval, SHA-256 content verification, bounded content-addressed storage, layer/diff-ID verification, staged root filesystem construction, Development image ingest/pull, and controlled image-to-runtime handoff tests.

Still gated

Real crun/runc acceptance, external-registry acceptance, full OCI conformance, rootless operation, networking, volumes, durable engine state, Compose, production migration, Stable qualification, and Docker replacement. Docker remains the current production runtime.

Open repository →

Development

GoreeCloud Code

Code

A first-party developer and source-control platform built around provider-neutral contracts so Git interoperability and forge infrastructure can evolve independently of the product experience.

Implemented foundation

Repository/branch/commit/issue/pull-request/provider-health reads, GoreeCloud-owned API and dashboard, Forgejo provider boundary, governed branch creation, durable attempted audit evidence, idempotency/replay safety, operation status, and read-only reconciliation assessment.

Still gated

Live forge read/write acceptance, authoritative reconciliation mutation, production Identity/application authorization, Wardveil, Privacy Shield, Everkeep, Mesh, distributed idempotency/reconciliation, exact GLAZE consumer acceptance, deployment, recovery evidence, and Stable qualification.

Open repository →
04

Boot & recovery

Portable boot media with safety as the first boundary.

Development

GoreeCloud Boot

Boot

A native, offline-first multiboot USB platform for booting, installing, recovering, diagnosing, and maintaining operating systems and GoreeCloud environments from removable media.

Implemented foundation

Validated read-only Linux device discovery; bounded sysfs holder/slave topology closure; caller-visible mount-namespace evidence; mounted-filesystem and active-swap exclusion; topology-aware revalidation; sector-aware GCBOOT/GCDATA planning; GPT metadata generation; catalog validation; and development-only regular-file GPT image tooling.

Still gated

Physical block-device writes, FAT32/exFAT creation, bootable USB images, UEFI boot runtime, Secure Boot, Windows-media compatibility, broader storage-topology qualification, signed releases, hardware compatibility acceptance, and Stable or production deployment.

Open repository →

Built to integrate, not bypass

Platform systems stay authoritative.

The six products can share platform capabilities, but none may manufacture identity, privacy, security, continuity, coordination, or design conformance by naming the platform system.

Glaze UIUser-facing design and accessibility contract
GoreeCloud IdentityIdentity and authentication authority
Wardveil SecuritySecurity, policy, trust, and audit authority
Privacy ShieldPrivacy, minimization, consent, and data-use authority
EverkeepBackup, restore, portability, and continuity authority
GoreeCloud MeshCapability discovery and coordination without authorization bypass
