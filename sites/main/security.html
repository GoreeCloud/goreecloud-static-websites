Responsible security reporting

Report security issues responsibly.

For security concerns involving GoreeCloud public systems or publicly available source, use the published security contact and include enough detail to reproduce and assess the issue without sending unnecessary sensitive data.

security@goreecloud.comsecurity.txt

01

Static public boundary

The main website is a static public information surface. It does not expose private GoreeCloud application administration through Cloudflare Pages.

02

Restricted browser capabilities

Published security headers constrain scripts, frames, forms, browser permissions, referrers, and cross-origin behavior.

03

Reviewed public artifact

The deployment build uses an explicit allowlist so repository-only files are not silently copied into the Pages artifact.

04

Evidence over badges

Security claims remain tied to applicable implementation, validation, and deployment evidence.

Authority boundary

Website controls are not Wardveil acceptance.

Wardveil Security by GoreeCloud is the first-party security system and shared security plane. A hardened website or Wardveil branding does not establish consumer acceptance or a broader protection claim.

Sentinel Fold is the approved standalone Wardveil Security mark. Its presence is identity, not evidence that every protection path has executed or been accepted.

Evidence boundary

One system cannot manufacture another system’s acceptance.

GoreeCloud Manager, Privacy Shield, Wardveil Security, Everkeep, Glaze UI, GoreeCloud Mesh, and GoreeCloud Identity retain distinct authorities and evidence. Website source validation is narrower than application, platform-system, or production-runtime acceptance.

Reporting scope

Public reporting is not testing authorization.

Do not open a public GitHub issue containing vulnerability details, credentials, private data, exploit instructions, or sensitive infrastructure information. Send reports to security@goreecloud.com and consult /.well-known/security.txt for the machine-readable policy.

This policy does not authorize testing of private family infrastructure, private services, accounts, devices, internal networks, administrative interfaces, credentials, or non-public data. GoreeCloud does not currently offer a bug bounty or guaranteed response timeline.
