Public Development Roadmap · September 6, 2026

From a homelab into an owned software ecosystem.

GoreeCloud is moving from a collection of self-hosted tools toward a cohesive personal and family cloud whose GoreeCloud application layer is original, native-from-the-ground-up software. Mature technical foundations can remain where replacing them would materially increase security, standards, protocol, codec, rendering, runtime, or interoperability risk. This public roadmap is intentionally higher level than internal task tracking: dates are not promises, priorities may change, and private infrastructure or security-sensitive work is omitted.

Now

Active development

Work already underway across the platform.

Source consolidation

Canonical public web ecosystem

GoreeCloud is consolidating every controlled static website into GoreeCloud/goreecloud-static-websites as the canonical source authority while preserving independent Cloudflare Pages projects and exact-revision deployment lifecycles. Existing production acceptance remains scoped to the revisions and source repositories that earned it until each site completes central source cutover, exact deployed-revision verification, and legacy-source retirement.

Stable consumer target

GLAZE UI V1.1 / 1.1.0

GLAZE UI V1.1 / 1.1.0 is the current Stable consumer target after the namespace reset. The web contract centers Canvas, Application content, and System Shell hierarchy; keeps durable content distinct from glazed system chrome; preserves 48-pixel interaction targets with a 56-pixel Touch Assistance path; and supports explicit Light, Dark, and Deep Dark appearance behavior plus reduced-motion, reduced-transparency, contrast, and forced-colors resilience. The immutable Stable web package has one known dangling CSS import, so current static-site migrations use a narrowly bounded fail-closed build workaround while exact consumer conformance remains separately gated.

Platform model

Seven Integral Platform Systems

GoreeCloud Manager, Privacy Shield, Wardveil Security, Everkeep, Glaze UI, GoreeCloud Mesh, and GoreeCloud Identity are Integral Platform Systems with distinct authority. Operations, privacy, security, continuity, design, coordination, identity, authentication, authorization, and related public claims remain tied to actual implementation and applicable authoritative evidence; one system cannot manufacture another system’s state.

Mandatory direction

Native application program

Every GoreeCloud application has the same required end state: original GoreeCloud-owned software at the product and application layer. Maintained forks and adopted complete application codebases are transitional migration, compatibility, testing, historical, or reference sources only. Production continuity is preserved until replacements satisfy separate migration and acceptance gates.

Active development

GoreeCloud AI and GoreeCloud Search

GoreeCloud AI develops as the first-party conversation, workspace, knowledge, RAG, research, file, tool, and orchestration application. GoreeCloud Search remains the first-party search and research gateway. Runtime and provider choices stay bounded implementation details rather than permanent product identity.

Active development

GoreeCloud Code

GoreeCloud Code is the first-party developer and source-control platform for repositories, collaboration, CI/CD, packages, security, and AI-assisted development. Forgejo is an initial replaceable infrastructure foundation rather than the permanent GoreeCloud product boundary.

Active development

GoreeCloud Mesh, Identity, and Manager

GoreeCloud Mesh coordinates explicit service relationships, capability context, governance, lifecycle events, and evidence-aware interoperability. GoreeCloud Identity owns identity, authentication, authorization, accounts, devices, credentials, sessions, and delegated authority. GoreeCloud Manager provides an operational control-plane surface without taking authority from the systems it observes or coordinates. Mesh and Manager must preserve Identity and producer-system authority boundaries.

Active development

Suite expansion

GoreeCloud Documents, GoreeCloud Messenger, GoreeCloud Gateway, GoreeCloud Quill, GoreeCloud File Manager, GoreeCloud Maps, GoreeCloud App Store, GoreeCloud Drive, GoreeCloud Sync, GoreeCloud Location, GoreeCloud Launcher, GoreeCloud Mail, GoreeCloud Notes, GoreeCloud Tasks, GoreeCloud Calendar, GoreeCloud Contacts, GoreeCloud Photos, GoreeCloud Music, GoreeCloud Video, and other focused applications continue advancing without collapsing into one oversized cloud product.

Active development

GoreeCloud App Store, File Manager, and Maps

GoreeCloud App Store is developing as the official multi-user application and service catalog with account-aware access. GoreeCloud File Manager is the first-party file-management experience for local and connected storage surfaces. GoreeCloud Maps is the mapping experience with explicit privacy, location, navigation, and identity boundaries. Public artwork remains limited to approved canonical assets.

Evidence-gated

Security, privacy, continuity, and operations

Wardveil Security, Privacy Shield, Everkeep, and GoreeCloud Manager continue substantive platform work while their public surfaces stay evidence-scoped. A website label, mark, platform name, successful build, or coordination record cannot manufacture protection, privacy, recovery, preservation, operational authority, or production state without applicable current implementation and evidence.

Active development

Drive, Sync, Documents, and personal context

GoreeCloud Drive, GoreeCloud Sync, GoreeCloud Documents, GoreeCloud Location, GoreeCloud Contacts, GoreeCloud Calendar, GoreeCloud Tasks, GoreeCloud Notes, and related applications continue developing focused data models, authorization boundaries, portability, recovery, collaboration, and interoperability rather than re-creating a single all-in-one cloud suite.

Current identity

Approved branding authority

GoreeCloud logos, product icons, system marks, artwork, and derivatives are sourced from the approved GoreeCloud branding authority. Facet, Sentinel Fold, Interlace, Everkeep, Identity, Manager, and other approved marks retain their canonical provenance. Products without approved canonical artwork use neutral presentation rather than fabricated, acronym-based, upstream, or provisional official identity.

Next

Near-term priorities

Publicly relevant work expected to follow current foundations.

In progress

Controlled GLAZE UI V1.1 website adoption

Migrate centralized website consumers from pre-reset Glaze 2.x source to GLAZE UI V1.1 through repository-local source, build, accessibility, visual, and artifact validation. Historical version references remain historical content; active runtime dependencies must use the current namespace-reset contract. The known immutable Stable import defect stays fail-closed and bounded rather than being silently recreated or ignored.

Planned

Central Cloudflare source cutover

Repoint each applicable Cloudflare Pages project to GoreeCloud/goreecloud-static-websites, preserve the correct site root/build/output contract, prove the exact deployed revision and custom-domain behavior, then retire repository-local legacy website copies only after no deployment or development dependency still requires them.

Planned

Identity Center publication acceptance

Publish the reviewed Identity Center artifact through the approved Cloudflare Pages path, bind and verify id.goreecloud.com, prove the exact deployed revision, and complete post-deployment visual, accessibility, link, asset, and truth-boundary checks without conflating website publication with production Identity acceptance.

Planned

Missing canonical product artwork

Create and approve required first-party artwork through the GoreeCloud branding authority before products without canonical marks are allowed to display official-looking icons or badges. Websites must continue suppressing surrogate identity until approved assets exist.

Planned

GoreeCloud Code authority transition

Advance repository migration, issues, pull requests, releases, packages, CI/CD, controlled runners, security workflows, and provider-neutral integrations while retaining optional external collaboration and mirrors where useful.

Planned

GoreeCloud AI Workspaces and native knowledge workflows

Advance persistent workspaces, document ingestion, embeddings, indexing, retrieval, source attribution, privacy-aware research, tool use, and representative recovery validation without overstating production maturity.

Planned

Integrated Suite experiences

Strengthen deliberate interoperability such as GoreeCloud Tasks and Calendar, Drive and Sync, Documents and Drive, Messenger and Contacts, App Store and Identity, Maps and Location, shared notifications, APIs, portability, and current Stable design behavior without unnecessary coupling.

Planned

Native device experiences

Advance GoreeCloud Launcher, Keyboard, Quill, Terminal, Browser, Messenger, Maps, and other device software through build, packaging, accessibility, real-device acceptance, and controlled release gates.

Planned

Release, distribution, and public documentation

Make supported versions, release notes, verification guidance, platform packages, approved download paths, public guides, and sanitized architecture explanations easier to understand without exposing private topology or operationally sensitive detail.

Later

Long-term direction

Strategic outcomes rather than scheduled commitments.

Future

Local-first primary infrastructure

Move the center of gravity toward GoreeCloud-owned local systems while preserving resilient remote access, backups, recovery, portability, and safe operating boundaries.

Future

Developer-platform independence

Move normal development, CI/CD, packages, release evidence, repository automation, security workflows, and AI-assisted development behind GoreeCloud Code and GoreeCloud-controlled execution while retaining replaceable infrastructure foundations.

Future

Advanced local AI independence

Expand GoreeCloud AI into justified tools, agents, multimodal capabilities, automation, browser interaction, and local research while keeping models, data, workflows, permissions, and knowledge under GoreeCloud control.

Future

Native product ownership

Complete the transition to original GoreeCloud applications at the product layer while retaining only narrowly justified mature technical dependencies and standards-compatible foundations.

Future

Long-term digital continuity

Keep data, memories, documentation, credentials, software, and operational knowledge portable, recoverable, understandable, and transferable across changing technologies.
